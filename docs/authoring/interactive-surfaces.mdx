title: Interactive surfaces
description: Keep selection state inside a surface, report the user's choice in an event, and use widgets with built-in gestures and animation.
---

A surface responds to taps on its own. A survey can highlight the answer the user picked, an onboarding screen can switch between options, and a paywall can move the selection between plans, all without code in your app.

## Selection state lives in the widget

Write the surface as a `StatefulWidget` and keep the selection in its `State` as a plain field. Use a `bool` for a choice between two options and an `int` for a longer row.

```dart
bool annualSelected = true;

void selectAnnual() => setState(() => annualSelected = true);
void selectMonthly() => setState(() => annualSelected = false);
```

Each option calls one of these methods from `onTap`. `build` reads the field to decide what looks selected.

The build turns those reads into state inside the delivered surface. The tap and the new selection happen there, and your app doesn't track the choice. Keep the field simple, like a `bool` or `int`, and change it with one assignment inside `setState`. Other `State` code still works on a paywall, a `@Screen(surface: ...)` or a split custom widget. It keeps running in your app for every design, and a design can read its values. A flow step's `State` has to become delivered state: simple fields, with one `setState` assignment per handler. A lifecycle method, a field of a type the build can't deliver, a nullable field with no value, or any other handler stops the build. The step's own `State` runs only when the step falls back to your compiled widget.

## Report the choice in an event

When the user confirms, send the choice to your app in an event. A screen fires a `SurfaceEvent` with `surfaceEvent`, as in [Write a surface](/authoring/write-a-surface). A paywall can read the field to pick the value it reports:

```dart
GestureDetector(
  onTap: paywallEvent(
    'continue',
    args: {'plan': annualSelected ? 'annual' : 'monthly'},
  ),
  child: /* the button */,
)
```

Your app gets the event in the mount's `onEvent` and acts on it. For a paywall, that's where your app starts the purchase with the store library it already uses. A published surface can't start a purchase or a restore itself. The build refuses the `paywallPurchase` and `paywallPriceFor` helpers and the reserved `purchase` and `restore` event names. An inline closure in your own `build()`, like `onPressed: () => cubit.purchase(plan)`, becomes an action. Your app runs its own closure.

The price on each option is text in the surface, or a value your app passes in as [host data](/authoring/host-data). Make sure the price the user sees and the plan the event reports belong together. [Products and purchases](/paywalls/products-and-purchases) shows the app side of a paywall purchase.

## Interactive text spans

Put a recognizer in a `TextSpan` to make part of the text tappable. Construct it inside the `TextSpan` as you would in Flutter, with the same surface event callbacks your buttons use. `TextSpan.children` can also use spread, collection `if` and collection `for`, including a `for` over host data. A tappable link looks like this:

```dart
import 'package:flutter/gestures.dart';

Text.rich(TextSpan(children: [
  const TextSpan(text: 'Read the '),
  TextSpan(
    text: 'guide',
    recognizer: TapGestureRecognizer()..onTap = surfaceEvent(openGuide),
  ),
]))
```

`TapGestureRecognizer`, `DoubleTapGestureRecognizer` and `LongPressGestureRecognizer` work with zero-argument callbacks. Native configuration such as supported devices and slop or duration values works too. Flutter does the hit testing for spans, and a parent's recognizer doesn't apply to its child spans.

A few rules apply to recognizers:

- Create a new recognizer at each use. With one shared between spans or surfaces, the `Text.rich` renders from your app.
- The runtime owns the recognizers you create. It settles pending gestures before it disposes retired resources.
- As in Flutter, a gesture in flight can finish its old callback after the text is replaced or removed.
- With a custom recognizer, manual lifecycle methods or an unsupported callback that takes details, the `Text.rich` renders from your app.

## Gestures and animation

Gesture and animation code lives in widgets compiled into your app, like a sheet you drag to dismiss, a pager you swipe or a detent that snaps. A surface sets their properties and receives their events when the gesture ends.

The Material library includes `RestageModalSheet`, `RestageDraggableSheet`, `RestagePager`, `RestageDropdown`, `RestageRadioGroup`, `RestageSegmentedButton` and `RestageToggleButtons`. You use them like any other widget. For behavior they don't cover, write the Flutter code as you normally would, and it renders from your app.

The [Widget catalog](/authoring/widget-catalog) lists these widgets.
