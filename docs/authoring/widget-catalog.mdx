The catalog is the set of widgets a surface can use. The current source has 124 built-in
widgets in three libraries, and your app can add its own.

You don't need to look widgets up before you write a surface. You write the Flutter
widgets you already know, and the build finds them in the catalog. The catalog matters
when you want to know what's covered, or when you want to add a widget.

## The three libraries

| Library | Widgets | Covers |
|---|---|---|
| [`restage_core`](https://pub.dev/packages/restage_core) | 61 | Layout, structure, and decoration: `Container`, `Column`, `Row`, `Stack`, `SizedBox`, `Padding`, `Center`, `Text`, `Image`, the implicit animations, and more. |
| [`restage_material`](https://pub.dev/packages/restage_material) | 47 | Material widgets: buttons, `Scaffold`, `AppBar`, `Card`, `ListTile`, chips, tabs, text fields, selection controls, and the interactive widgets below. |
| [`restage_cupertino`](https://pub.dev/packages/restage_cupertino) | 16 | iOS-style widgets: `CupertinoButton`, navigation bar and page scaffold, list sections, switches, sliders, pickers, and text fields. |

## You write ordinary Flutter

There are no separate widget classes to learn. You write `Container`, `Text`,
`Column`, `FilledButton`, and the rest with their normal Flutter APIs, and the build
maps each one to its catalog entry. A surface that uses `CupertinoButton` renders it
from the Cupertino library.

### Transforms

Use `Transform.translate` to move a child when painting while keeping its layout
space unchanged:

```dart
Transform.translate(
  offset: const Offset(12, -4),
  child: const Text('Moved'),
)
```

Offsets, `transformHitTests`, and `filterQuality` retain Flutter's behavior.

`Transform.scale` supports uniform scaling through `scale`, or independent axes
through `scaleX` and `scaleY`, including zero and negative factors:

```dart
Transform.scale(
  scaleX: -1,
  scaleY: 1.5,
  alignment: Alignment.center,
  child: const Text('Scaled'),
)
```

Origin, alignment, filtering, and hit testing follow Flutter. Omitting alignment
uses the native center default; passing `alignment: null` preserves null.

### AppBar

`AppBar` supports its layout, text and icon styles, system-bar styles, opacity,
animation, and accessibility options. Use ordinary Flutter values such as
`TextStyle`, `IconThemeData`, and `SystemUiOverlayStyle`:

```dart
import 'package:flutter/material.dart';
import 'package:flutter/services.dart';

AppBar(
  backgroundColor: Colors.transparent,
  systemOverlayStyle: SystemUiOverlayStyle.dark.copyWith(
    statusBarColor: Colors.transparent,
  ),
  iconTheme: const IconThemeData(size: 24, color: Colors.black),
  actionsIconTheme: const IconThemeData(color: Colors.blue),
  title: const Text('Welcome'),
)
```

Omitted styles, `centerTitle`, and `toolbarHeight` retain Flutter's theme and
platform defaults. The `bottom` slot accepts a `TabBar` or `PreferredSize`, and
`flexibleSpace` places content behind the toolbar.

`IconThemeData` supports its constructor, `IconThemeData.fallback()`,
`copyWith`, and `IconThemeData.lerp`. An `AppBar` used as another AppBar's
`bottom` may take a nullable `toolbarHeight`.

`notificationPredicate` accepts a depth check such as
`(notification) => notification.depth == 1`, where the depth is an `int`.
Omitting it keeps Flutter's default predicate.

### Tab pages

Combine `DefaultTabController`, `TabBar`, and `TabBarView` as you would in Flutter:

```dart
DefaultTabController(
  length: 2,
  child: Scaffold(
    appBar: AppBar(
      bottom: const TabBar(tabs: [Tab(text: 'One'), Tab(text: 'Two')]),
    ),
    body: const TabBarView(
      children: [Text('First page'), Text('Second page')],
    ),
  ),
)
```

`TabBarView` uses the nearest `DefaultTabController` and supports `clipBehavior`,
`dragStartBehavior`, and `viewportFraction`, including fractions greater than one.
Provide bounded space, such as the `Scaffold.body` above, and matching controller,
tab, and page counts. Explicit `controller` and `physics` expressions are not
currently compiled.

## Widgets with built-in gestures and animation

`restage_material` includes widgets whose gesture and animation code is compiled into
your app. A surface sets their properties and receives their events:

- `RestageModalSheet` and `RestageDraggableSheet` for bottom sheets you drag.
- `RestagePager` for pages you swipe.
- `RestageDropdown`, `RestageRadioGroup`, `RestageSegmentedButton`, and
  `RestageToggleButtons` for choosing an option.

`restage_core` adds motion widgets (`RestageMotion`, `RestageFadeIn`, `RestagePulse`,
`RestageStagger`) and number and price formatting (`RestagePrice`,
`RestageFormattedNumber`).

## Your own widgets

To use a widget from your design system in a surface, annotate it with
`@RestageWidget` and it joins the catalog. See [Custom widgets](/authoring/custom-widgets).

## One catalog for every surface

The same widgets build an onboarding flow, a message, a survey, a paywall, a single
card, or a whole screen. There is no separate catalog per surface type.
