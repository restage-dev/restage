title: Flows
description: Connect your own Flutter screens into onboarding, messages, surveys, and other multi-screen surfaces.

A flow connects screens into an onboarding, a multi-step message, a survey or any other
multi-screen surface. You write each screen as an ordinary Flutter widget and list how
they connect in a short Dart flow definition. The build checks the graph
and generates a typed `*Surface` widget that you mount in your app.

Use a flow when you want Restage to handle the order of screens and the moves between
them. If your app router already does that, it can keep showing individual surfaces.
For existing paywalls, `Navigator.push` and `Navigator.pop` calls can
[compile into a flow automatically](/paywalls/overview#multi-screen-paywalls). You
don't write a flow definition for that.

Every flow and every standalone screen declares a category in source. `Surface` has
five values: `onboarding`, `message`, `survey`, `paywall` and `general`. Use
`Surface.general` when nothing else fits. Where a file lives has no effect on its
category.

## Screens and events

A screen inside a flow takes a plain `@Screen()` and gets the flow's category. Save
this as `lib/screens/welcome.dart`:

```dart
import 'package:flutter/material.dart';
import 'package:restage/restage.dart';

part 'restage.generated/welcome.restage.g.dart';

@Screen()
final class WelcomeScreen extends StatelessWidget {
  const WelcomeScreen({super.key});

  static const next = SurfaceEvent<void>('next');

  @override
  Widget build(BuildContext context) {
    return FilledButton(
      onPressed: surfaceEvent(next),
      child: const Text('Continue'),
    );
  }
}
```

`SurfaceEvent<T>` declares a typed event. `surfaceEvent(event)` turns it into a normal Flutter callback. The flow refers to the static field, and you never write an event string in the flow or in your app code.

A screen you publish on its own declares its category instead, like
`@Screen(surface: Surface.message)`. See [standalone screens](#standalone-screens).

Add the final screen in `lib/screens/profile.dart`:

```dart
import 'package:flutter/material.dart';
import 'package:restage/restage.dart';

part 'restage.generated/profile.restage.g.dart';

@Screen()
final class ProfileScreen extends StatelessWidget {
  const ProfileScreen({super.key});

  static const finish = SurfaceEvent<void>('finish');

  @override
  Widget build(BuildContext context) => FilledButton(
        onPressed: surfaceEvent(finish),
        child: const Text('Finish setup'),
      );
}
```

## Define the flow

Annotate a top-level `FlowDefinition` with `@FlowGraph`. Each transition names an event
and the screen it leads to. `Transition.complete` ends the flow with a result. Save
this as `lib/flows/welcome_flow.dart`:

```dart
import 'package:restage/restage.dart';

import '../screens/profile.dart';
import '../screens/welcome.dart';

part 'restage.generated/welcome_flow.restage.g.dart';

@FlowGraph(surface: Surface.onboarding)
const welcomeFlow = FlowDefinition(
  start: WelcomeScreen,
  transitions: [
    Transition(
      WelcomeScreen.next,
      to: ProfileScreen,
    ),
    Transition.complete(ProfileScreen.finish),
  ],
);
```

When a file holds one flow, the flow id is the file name. This flow is `welcome_flow`.
Pass `id:` if you might move or rename the file, or if the file holds more than one
flow.

## Mount the flow

Run `dart run build_runner build`, import `flows/welcome_flow.dart`, and mount the
generated `WelcomeFlowSurface`:

```dart
WelcomeFlowSurface(
  onComplete: (result) {
    Navigator.of(context).pushReplacementNamed('/home');
  },
)
```

Use this inside your app's widget tree, where `/home` is a route your app defines. The mount installs its own widgets and keeps your compiled flow as the fallback, and it can run offline without any surface assets. Its result type is `WelcomeFlowResult`.

With [hosted delivery](/delivery/hosted-delivery) set up, the same mount can show a
compatible published version. It declares its placement for you, with no placement id to pass.

### Direct flow mounts

`RestageFlowGraph<WelcomeFlowResult>(flow: welcomeFlowRef, ...)` is the lower-level
widget. Use it when you want to pass the reference and the fallback
yourself. [Bundled assets](/delivery/bundled-assets#mount-a-bundled-flow) has a full
example. With `RestageFlowView`, your app owns the controller and the navigation
controls. See [Navigation](/flows/navigation-and-chrome).

## State and decisions

Declare each piece of flow state once as a `FlowStateRef<T>`. Reuse that reference to
capture an event's value, write a value, test a condition, or put it in the flow's
result. A `Decision` picks the next screen from that state:

```dart
const mode = FlowStateRef<String>('mode');

final route = Decision(
  'route',
  branches: [
    Branch(
      when: mode.equals('guided'),
      to: GuidedScreen,
    ),
  ],
  otherwise: ExploreScreen,
);
```

A transition can lead to a screen, a `Decision`, a `Completion` or a `Subflow` (a child
flow). [Branching](/flows/branching) has a full example. [Host actions](/flows/host-actions)
shows how a flow calls code in your app.

Some graphs don't fit a constant definition, like ones with custom action or result
handling. Write those as a class with the same annotation and build the graph in
`buildFlow()`:

```dart
@FlowGraph(surface: Surface.onboarding)
final class ComplexFlow extends RestageFlow {
  const ComplexFlow();

  @override
  FlowDef buildFlow() {
    final done = endState('done');

    return flow(
      initial: welcomeScreenRef,
      states: [
        screen(welcomeScreenRef).on(WelcomeScreen.next).goTo(done),
        end(done, result: {}),
      ],
    );
  }
}
```

## Paywalls inside flows

A screen with an explicit category must match the flow it's in. A plain `@Screen()`
takes the flow's category. `@Paywall()` is the exception. It's always
`Surface.paywall`, and it can be a step in a flow of any category.

```dart
@FlowGraph(surface: Surface.general)
const accountRecovery = FlowDefinition(
  start: IdentifyAccountScreen,
  transitions: [
    Transition(
      IdentifyAccountScreen.showPaywall,
      to: GeneralPaywall,
    ),
    Transition.complete(GeneralPaywall.complete),
  ],
);
```

`GeneralPaywall` is a `@Paywall()` widget that declares its own
`static const complete = SurfaceEvent<void>('complete')`. Mount the journey with the
generated `AccountRecoverySurface`. The flow owns the events. You can't pass a
standalone paywall's purchase handlers directly to a flow. When a transition has to wait for a
purchase or other app work, use a [host action](/flows/host-actions).

## Standalone screens

A screen you publish on its own declares its category. You mount it with its generated
`<ClassName>Surface`. Add the `part` line as described in
[Write a surface](/authoring/write-a-surface):

```dart
@Screen(surface: Surface.general)
final class MaintenanceNotice extends StatelessWidget {
  const MaintenanceNotice({super.key});

  static const dismiss = SurfaceEvent<void>('dismiss');

  @override
  Widget build(BuildContext context) => FilledButton(
        onPressed: surfaceEvent(dismiss),
        child: const Text('Dismiss'),
      );
}

MaintenanceNoticeSurface(
  onEvent: (event) {
    if (event is MaintenanceNoticeSurfaceDismissEvent) {
      Navigator.of(context).maybePop();
    }
  },
)
```

Generated mounts work for every category and keep your compiled widget as the
fallback. A flow step that renders app code gets its own step mount. That mount
runs the step's `build()` the same way. Bind that step's screen builder, or the flow is
unavailable. You can still mount `RestageScreen<E>` and `RestagePaywall` directly.

## What you can change without an app release

By default a flow is typed. You can publish new content, copy and layout for its
screens, and your app gets a typed result class. Changing the shape of the graph, like
adding a screen or rerouting a transition, needs a new app build.

To change the graph over the air, declare the flow with general delivery:

```dart
@FlowGraph(
  surface: Surface.onboarding,
  delivery: FlowDeliveryMode.general,
)
```

A published version can then add, remove or reorder screens and change where
transitions lead. It can only use the host actions and custom events your installed app
already declares. In return, `onComplete` gets a plain `Map<String, Object?>` instead of
a generated result class. The generated mount uses that type for you. With a direct
mount, use `RestageFlowGraph<Map<String, Object?>>`.

`FlowDeliveryMode` and `Surface` are separate choices. `Surface.general` is a category, while `FlowDeliveryMode.general` controls what a published version can change.

## Push and publish

The build writes a publication manifest to
`.restage/build/metadata/restage.publication.json`, and the CLI reads it to find your
surface's files. Push a version by its id, then publish it to make it live:

```sh
restage surface push welcome_flow
restage surface publish welcome_flow
```

A push uploads a version and changes nothing that's running. You can name the `.dart`
file instead of the id. If the file produced more than one surface, `--all` pushes all
of them. `--type` is optional. If you pass it, the CLI checks that the surface has that
type.

## Older annotations

`@ScreenSource`, `@PaywallSource` and `@FlowSource` are deprecated and still work. In
new code, use `@Screen`, `@Paywall` and `@FlowGraph`.

## What ships in the app

Flow documents and generated assets ship inside your app, and anyone can read them.
Don't put credentials, private tokens or secret business rules in them. Custom events,
results and action arguments are checked against their declarations before they reach
your app code.
