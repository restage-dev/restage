---
title: RevenueCat
description: Show RevenueCat packages and localized prices, and measure completed purchases in paywall experiments.
---

`restage_revenuecat` connects a Restage paywall to the RevenueCat setup your app already has. You give it an offering. The paywall gets the offering's packages and localized prices, and each purchase button sends the identifier of the package it shows. RevenueCat stays the source for subscription and entitlement information.

<Callout type="info">
The adapter lives in the [Restage source repository](https://github.com/restage-dev/restage/tree/main/packages/restage_revenuecat). It isn't on pub.dev yet.
</Callout>

## Adapter helpers

| API | Use |
| --- | --- |
| `revenueCatEventHandler` | Buys the selected package, or restores, through the RevenueCat offering you pass in. |
| `revenueCatOfferingData` | Builds the display context for a direct `RestagePaywall` mount. |

The adapter exports functions only. There's no prebuilt paywall or scope widget, and you configure RevenueCat in your app. `RevenueCatPaywallSurface` below is generated from the example's Flutter widget. Follow the same pattern for your own design.

Use that generated mount and its typed constructor inputs. The data-map helper is for the [direct mount API](#direct-mount-data-helper).

## Connect an offering

Configure RevenueCat as usual, then fetch the offering before you mount the paywall. These snippets come from the [runnable adapter example](https://github.com/restage-dev/restage/tree/main/packages/restage_revenuecat/example). Set up delivery once at startup:

```dart
import 'package:restage/restage.dart';

import 'restage_surfaces.g.dart';

// Inside main(), after WidgetsFlutterBinding.ensureInitialized():
Restage.configureWithInstalledCatalog(
  apiKey: const String.fromEnvironment('RESTAGE_API_KEY'),
  baseUrl: const String.fromEnvironment('RESTAGE_BASE_URL'),
  surfaces: restageSurfaces,
);
```

Once RevenueCat is configured, load the offering and mount the paywall:

```dart
import 'package:purchases_flutter/purchases_flutter.dart';
import 'package:restage/restage.dart';
import 'package:restage_revenuecat/restage_revenuecat.dart';

import 'revenuecat_upgrade.dart';

// Inside your app's async paywall-loading method:
final offering = (await Purchases.getOfferings()).current;
if (offering == null) return;

final paywall = RevenueCatPaywallSurface(
  packages: [
    for (final package in offering.availablePackages)
      PaywallPackage(
        identifier: package.identifier,
        priceString: package.storeProduct.priceString,
      ),
  ],
  onEvent: revenueCatEventHandler(
    offering: offering,
    onCustomerInfo: (info) {
      // Run your app's usual RevenueCat entitlement checks.
    },
    onError: (error, stackTrace) {
      // Handle RevenueCat errors here, including cancellation.
    },
  ),
);
```

Use the same offering for the data and the handler. The handler buys the selected RevenueCat package with its configured offer. An identifier that isn't in the offering produces an error. Restore calls RevenueCat's restore and hands the customer information to `onCustomerInfo`.

The offering is [local host data](/authoring/host-data). The data helper leaves out its metadata and customer information, and the offering is never uploaded.

## Author the generated mount

Declare the fields your surface reads as host data in `lib/revenuecat_upgrade.dart`:

```dart
import 'package:flutter/material.dart';
import 'package:restage/restage.dart';

part 'restage.generated/revenuecat_upgrade.restage.g.dart';

final class PaywallPackage {
  const PaywallPackage({required this.identifier, required this.priceString});

  final String identifier;
  final String priceString;
}

@Paywall()
class RevenueCatPaywall extends StatelessWidget {
  const RevenueCatPaywall({required this.packages, super.key});

  final List<PaywallPackage> packages;

  @override
  Widget build(BuildContext context) => Column(
        children: [
          for (final package in packages)
            FilledButton(
              onPressed: paywallEvent(
                'revenuecat.purchase',
                args: {'packageIdentifier': package.identifier},
              ),
              child: Text(package.priceString),
            ),
          TextButton(
            onPressed: paywallEvent('revenuecat.restore'),
            child: const Text('Restore purchases'),
          ),
        ],
      );
}
```

Run `dart run build_runner build` to generate `RevenueCatPaywallSurface`. It keeps your compiled widget as the fallback, and bundling assets is optional.

The surface decides the layout and which packages appear. Your app passes in the current offering each time it opens the paywall. Keep the event names `revenuecat.purchase` and `revenuecat.restore`, because plain `purchase` and `restore` are reserved.

## Direct mount data helper

A generated mount sends the constructor values you pass. For a direct `RestagePaywall` mount, `revenueCatOfferingData(offering)` gives you the same display data as a context map. Direct mounts also need widget registration and a fallback.

The map has the offering's `identifier` and a `packages` list. Each package has `identifier`, `productIdentifier`, `priceString` and `currencyCode`. It also has `subscriptionPeriod`, `freeTrial` and `introductoryPrice` when they're available. Offer phases have a localized `priceString`, plus a `period` and `cycles` when RevenueCat supplies them.

An available offer doesn't mean the user is eligible for it. The store decides that during purchase.

## Run a price test

To test $49 against $59 for an annual plan, add two packages to the offering, such as `annual_49` and `annual_59`, each with its store product. Each card shows the package's `priceString`. Other currencies keep their localized prices.

Publish one paywall version that picks `annual_49` and another that picks `annual_59`. The first version's package loop can look like this:

```dart
for (final package in packages)
  if (package.identifier == 'annual_49')
    FilledButton(
      onPressed: paywallEvent(
        'revenuecat.purchase',
        args: {'packageIdentifier': package.identifier},
      ),
      child: Text(package.priceString),
    ),
```

Select the two published versions as experiment arms and choose **Purchase conversion** as the primary metric. Both packages must be in the offering the app fetches.

Once the app has this adapter, a new price point is a package in RevenueCat and a paywall version in Restage. You don't need an app release.

## Publish holiday pricing

Add an `annual_holiday` package next to `annual_standard` in RevenueCat. Publish a holiday paywall version that picks `annual_holiday` and shows its live price. Activate that version for the promotion. When it ends, roll back to the version that picks `annual_standard`.

Keep both packages available for the whole rollout and rollback. That includes while some apps still hold an earlier offering.

The app keeps the same adapter integration. Each change is a package in RevenueCat and a paywall version in Restage, with no app release.

## Understand purchase conversion

**Purchase conversion** shows up once you publish a paywall version after adding this integration. Versions published before purchase reporting existed keep their tap metrics.

The SDK ties each event to the paywall view (the exposure) that sent it. When RevenueCat reports success, the handler calls `Restage.measurement.reportPurchase` with that event and the package and product identifiers. If the paywall refreshes or closes during checkout, the purchase still counts for the version it came from. The report has no customer or store transaction identifier.

**Purchase conversion** records whether a paywall exposure led to at least one successful purchase that the app reported within 24 hours. Several purchases from one exposure count as one conversion. Without an experiment, the rate divides by the exposures shown. In an experiment, it divides by the units assigned to each arm. The dashboard and MCP show these results in the same experiment result view.

Failures, cancellations and restores send no purchase report. A report that's rejected or lost in transport can't count as a conversion. A failed report doesn't change the purchase result in your app.

Purchase counts update as reports arrive. Counts too small to show safely are withheld, like other results. Results stay marked provisional while exposures are pending. Each exposure has a 24-hour attribution window, then a 24-hour grace period for reports to arrive. The experiment verdict uses only exposures whose windows have closed. Purchases outside the attribution window don't count.

Without an accepted purchase report, a tap metric only measures button activation. It can't tell you whether checkout completed.

RevenueCat's Flutter purchase result doesn't include the amount or currency paid, and the adapter leaves them unknown. Catalog prices remain display data, and purchase reports feed experiment results only. Restage doesn't record them as revenue, and they don't count toward billing.
