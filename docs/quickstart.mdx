title: Quickstart
description: Annotate a Flutter widget and mount it with your compiled widget as the fallback, without surface assets or a backend.
---

This guide turns one widget into a surface and shows it in your app. The example is a small paywall, but the steps are the same for onboarding screens, messages, surveys and any other screen.

Everything runs locally. You don't need a Restage account or a backend.

## 1. Add the packages

Restage 2.0 needs Flutter 3.44 or newer. Add `restage`, `restage_material`, `restage_codegen` and `build_runner` to your app's `pubspec.yaml`:

```yaml
dependencies:
  flutter:
    sdk: flutter
  restage: ^2.0.0
  restage_material: ^2.0.0

dev_dependencies:
  flutter_test:
    sdk: flutter
  build_runner: ">=2.4.0 <3.0.0"
  restage_codegen: ^2.0.0
```

Add these to what your project already lists. A fresh `flutter create` app already has `flutter_test` and `flutter_lints`. Then fetch the packages:

```sh
flutter pub get
```

To try unreleased changes, keep the `^2.0.0` dependencies and add these overrides. They take the packages from the repository's `main` branch. `rfw_catalog_schema` needs one too because the code generator also asks for it from pub.dev:

```yaml
dependency_overrides:
  restage:
    git:
      url: https://github.com/restage-dev/restage.git
      ref: main
      path: packages/restage
  restage_material:
    git:
      url: https://github.com/restage-dev/restage.git
      ref: main
      path: packages/restage_material
  restage_codegen:
    git:
      url: https://github.com/restage-dev/restage.git
      ref: main
      path: packages/restage_codegen
  rfw_catalog_schema:
    git:
      url: https://github.com/restage-dev/restage.git
      ref: main
      path: packages/rfw_catalog_schema
```

If you use a coding agent, install the Restage skill too, and the agent writes surfaces the way the build expects. See [Coding agents](/tools/coding-agents).

The `restage` CLI can do this step for you with `restage init`, but it's optional and isn't on pub.dev yet. The [CLI guide](/tools/cli) covers installing it from source.

## 2. Write a paywall

Create `lib/paywalls/pro_upgrade.dart`:

```dart
import 'package:flutter/material.dart';
import 'package:restage/restage.dart';

part 'restage.generated/pro_upgrade.restage.g.dart';

@Paywall()
class ProUpgradePaywall extends StatelessWidget {
  const ProUpgradePaywall({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: SafeArea(
        child: Padding(
          padding: const EdgeInsets.all(24),
          child: Column(
            mainAxisAlignment: MainAxisAlignment.center,
            children: [
              Text(
                'Go Pro',
                style: TextStyle(
                  fontSize: 28,
                  fontWeight: FontWeight.w700,
                  color: Theme.of(context).colorScheme.primary,
                ),
              ),
              const SizedBox(height: 8),
              const Text('Everything you need, in one plan.'),
              const SizedBox(height: 24),
              FilledButton(
                onPressed: paywallEvent('continue'),
                child: const Text('Continue'),
              ),
            ],
          ),
        ),
      ),
    );
  }
}
```

`@Paywall()` marks the widget as a surface, and its id, `pro_upgrade`, comes from the file name. Pass an explicit id if you want a different one, or one that survives renaming the file.

`paywallEvent('continue')` sends an event to your app when the button is pressed. The `Theme.of(context)` read resolves from the live widget tree when the surface renders, and the surface follows your theme.

If the compiler can't deliver something, it renders that part from your app and lists it in `restage build report`. It follows `final` locals, same-file constants, helper methods and `for` loops over constant lists. Most ordinary Flutter compiles as written. [Authoring constraints](/authoring/constraints) lists the limits. To show data your app already has, see [Host data](/authoring/host-data).

## 3. Generate the artifacts

Run the build:

```sh
dart run build_runner build
```

The build writes the generated mount to `lib/paywalls/restage.generated/pro_upgrade.restage.g.dart` and the publishable artifacts under `.restage/build/`. When you push a surface, the CLI finds them through `.restage/build/metadata/restage.publication.json`.

Leave `bundled_runtime` at its default, `false`. You don't need to set it in `build.yaml` or add anything to Flutter's asset list. The generated mount keeps your compiled widget as its fallback and works offline.

Commit the generated Dart, and these two files that keep Restage ids stable across builds:

- `.restage/measurement-state.json`
- `.restage/wire-ids.events.jsonl`

`.restage/build/` is build output and doesn't go in your app's assets. [Bundled assets](/delivery/bundled-assets) covers the optional workflow of shipping artifacts inside the app.

## 4. Mount the generated paywall

Put `ProUpgradePaywallSurface` wherever the paywall belongs. It installs the widgets it needs and declares its placement for you, with the ordinary constructor. When no hosted content is available, it shows your compiled widget. Put this in `lib/main.dart`:

```dart
import 'package:flutter/material.dart';

import 'paywalls/pro_upgrade.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        body: ProUpgradePaywallSurface(
          onEvent: (event) => debugPrint('$event'),
        ),
      ),
    );
  }
}
```

This offline example needs no hosted configuration. To fetch published versions, configure delivery at startup. Measurement is on by default with hosted delivery, while live refresh is opt-in. [Hosted delivery](/delivery/hosted-delivery) covers the setup.

Run the app:

```sh
flutter run
```

`onEvent` is where your app reacts to the surface. When the `continue` event arrives, run the purchase through the store library your app already uses. A purchase closure written inline in the paywall, like `onPressed: () => cubit.purchase()`, also works, as an action.

## 5. Rebuild while editing

Run the build again after a source change, or leave it watching:

```sh
dart run build_runner watch
```

With no hosted content, the mount shows your compiled widget, and Flutter's usual hot-reload rules apply. Rebuild after you change the surface, its parameters or its events. For published content, [live refresh](/delivery/live-refresh) can update a surface that's already on screen.

Release builds need no special flags. The build records which widgets and icons your app uses. A release keeps only those, and Flutter's icon tree-shaking works as usual. Don't pass `--no-tree-shake-icons`, because it puts the whole icon font back into the app.

The [Starters](/starters) page links to small onboarding, message, paywall, custom-widget and host-data examples. When you're ready to publish, go to [Hosted delivery](/delivery/hosted-delivery).
