> **Unreleased A2UI 1.0 candidate integration.** These instructions describe the
> repository/workspace packages, not the published `restage_a2ui 0.2.0` or
> `restage_codegen 2.0.0` releases. Use the repository example while qualifying
> the candidate. Upstream pins are `a2ui_flutter: 0.0.1-wip003` and
> `a2ui_core: ^0.4.0`, with Dart >=3.11.0, Flutter >=3.38.0 and
> `json_schema_builder` >=0.1.7. Recheck upstream and reconcile hosted package
> constraints before release; protocol 1.0 is not declared stable here.

`restage_codegen` can turn your `@RestageWidget` widgets and `@Screen`
screens into an A2UI catalog for Google's [`a2ui_flutter`](https://pub.dev/packages/a2ui_flutter)
renderer. A generative-UI model can then build screens from your widgets. The catalog
describes your own widget classes only. Flutter, Material, Cupertino, and Restage
built-in widgets aren't copied into it.

The order is: write annotated Flutter widgets, generate the catalog, then connect
it to A2UI in your app. This works before any Restage upload or publication;
`restage build push` is only for dashboard previews. Restage doesn't fetch, host,
or stream A2UI payloads. Your app or your model session does that.

## Add the dependencies

```yaml
dependencies:
  a2ui_flutter: 0.0.1-wip003
  a2ui_core: ^0.4.0
  json_schema_builder: ^0.1.7
  restage_a2ui:
    path: ../restage_a2ui
  rfw_catalog_schema: ^2.0.0

dev_dependencies:
  build_runner: ">=2.4.0 <3.0.0"
  restage_codegen:
    path: ../restage_codegen
```

`a2ui_flutter` renders the payloads. The generated catalog imports `restage_a2ui`, which also
provides the check before render described below. The code generator runs at build time
and doesn't ship in your app.

## Turn on the A2UI builder

The A2UI builder is off by default, because its generated Dart imports `a2ui_flutter`. Add a
`build.yaml` to the package that declares your widgets:

```yaml
targets:
  $default:
    builders:
      restage_codegen:user_a2ui_catalog:
        enabled: true
```

These emitter options do not require RFW bundling. Leave `bundled_runtime` at its
default, `false`; no generated surface assets need to be added to the app.

Keep the other Restage builders on if the app also delivers Restage surfaces. For an
A2UI-only package you can turn them off, as the
[`restage_a2ui` example](https://github.com/restage-dev/restage/tree/main/packages/restage_a2ui/example)
does.

Each widget library in the catalog needs a `@RestageLibrary(capabilityVersion:)`
declaration. Raise the version when you add a widget or change how one renders. See
[Custom widgets](/authoring/custom-widgets#3-declare-exact-library-ownership) for the
barrel file.

## Describe components for the model

Add a description to every catalog component and public input, including screen
inputs. Dartdoc supplies the schema description the model reads;
`@RestageProperty(description: ...)` is an alternative for inputs. `@a2ui.Config.usage('…')` tells the model when to
pick the widget, and becomes its line in the catalog's system prompt. Without it, the
description is used. `@a2ui.Config.writeBackValue('propertyName')` says which value a
callback writes back when that isn't clear. A value property paired with a
`ValueChanged` callback of the same type becomes a two-way binding.

[Custom widgets](/authoring/custom-widgets#4-add-useful-target-specific-configuration)
and [Write a surface](/authoring/write-a-surface#one-source-three-targets) show full
examples that compile in the public example package.

A standalone `@Screen(surface: ...)` becomes one component named after its id. The
generated builder constructs your real screen and passes its `SurfaceEvent` calls
through. The screen's widget tree isn't split into A2UI components. A bare
`@Screen()` used inside a flow can also become a component.
`@FlowGraph` and `@Paywall` aren't part of the A2UI catalog.

The generator finds these declarations anywhere in the package, whatever the directory.

Properties can use nested data classes, lists of objects, string-keyed maps, named
records, enums, and scalar lists. The generator describes them in the schema and
rebuilds the Dart values in the generated builder. Sealed-class unions aren't supported
yet. A required unsupported property stops the build; an optional one can be left
out only when leaving it out gives the same result as its default.

## The payload shape

Generated components keep protocol `id` and `component` separate from constructor
inputs. For ordinary names, inputs use top-level `props_<DartName>` properties:

```json
{
  "id": "showcase",
  "component": "CatalogShowcase",
  "props_title": "Catalog proof",
  "props_status": "ready",
  "props_hero": "hero_component_id",
  "props_details": ["detail_a_id", "detail_b_id"],
  "props_footer": "footer_component_id",
  "props_data": {"note": "Generated once", "count": 2}
}
```

Ordinary constructor names use `props_<DartName>` when that name is a valid
upstream UAX31 identifier and the source name does not start with `encoded_`.
Other names, including `$value`, and all source names starting with `encoded_`
use `props_encoded_<hex>`. The hex concatenates the source name's UTF-16 code
units as exactly four lowercase digits each; `$value` becomes
`props_encoded_002400760061006c00750065`. Reserving `encoded_` prevents a normal
source name from colliding with an encoded name. Producers must use the property
keys in the generated catalog schema and instructions. Dart constructor arguments
and nested rich-data keys keep their original names. Nested rich-data keys that start with `@` are written as `@@` on the wire; the runtime unescapes them.

Single and list children can use any authored input name. A constructor input
named `props` becomes `props_props`.

## Generate the catalog

Run:

```sh
dart run build_runner build
```

The build writes two files:

- `lib/generated/restage_a2ui_catalog.g.dart` has `buildRestageCatalog()`, which returns
  the a2ui_flutter `CatalogImplementation`, and `restageA2uiCapability`, which records what that catalog
  provides.
- `.restage/build/a2ui/restage_a2ui_catalog.a2ui.json` is a standard A2UI catalog
  document with each component's schema. Give it to whatever produces payloads, such as
  your model prompt or your server.

Keep the generated `restageA2uiCatalogId` with that exact catalog. The payload
producer must use it in `createSurface` messages. To combine
`buildRestageCatalogItems()` with another catalog, give the combined catalog a new
id of your own and give that catalog to the producer.

## Connect A2UI and check cached bundles

Use the same catalog for the check and the processor:

```dart
final check = RestageA2uiPreRenderCheck(
  catalogs: [catalog],
  installed: restageA2uiCapability.installedCapability,
  validationConfig: ValidationConfig.strict,
);
final processor = MessageProcessor<ComponentImplementation>(
  catalogs: [catalog],
  defaultVersion: A2uiProtocolVersion.v1_0,
  validationConfig: ValidationConfig.strict,
);
```

Check the complete bundle before unwrapping a Restage sidecar, then pass its
payload to `processor.processMessages`. Mount
`A2uiSurface(surface: processor.model.getSurface(surfaceId)!)` after creation,
and dispose the processor with its owner. Handle renderer errors and keep a
native fallback available.

A complete initial message is:

```dart
{
  'version': 'v1.0',
  'createSurface': {
    'surfaceId': 'example',
    'catalogId': restageA2uiCatalogId,
    'components': [
      {'id': 'root', 'component': 'BareCatalogCard', 'props_label': 'Hello from A2UI'},
    ],
  },
}
```

Preflight validates message envelopes, catalog resolution and component schemas
without invoking functions. Restage sidecars additionally require the installed
library/version capability set. Give it the processor's `validationConfig`: it
applies that config to each message as the processor does, and also rejects a
finished bundle with no surface, an empty surface, a missing root, a dangling
reference or a cycle. Catalog IDs route schemas and
are not capability authority.

Give the producer the standard catalog JSON and its authored `instructions`.
Your app owns the model connection and `onAction` transport. A catalog does not
start an agent session or register itself with a remote server.

## Migrating an existing integration

Regenerate the catalog and migrate producer/cached documents together. Generated
inputs now use the generated top-level property names. Ordinary names retain
`props_<DartName>`: `props` becomes `props_props`, and `id` becomes `props_id`.
Names that fail upstream UAX31 validation or start with `encoded_` use the
reserved UTF-16 hex encoding described above. Read the regenerated schema when
migrating producers and cached inputs; keep nested business-data keys unchanged. Keep
protocol `id`, `component`, and `catalogId` separate. Dynamic references use
`{"@path":"/answer"}` and `{"@call":"functionName"}`. Do not rename ordinary
business-data keys, `updateDataModel.path`, or child-template `path` fields.

Run `dart fix --apply` after updating the repository packages. The shipped fix
wraps `RestageA2uiPreRenderCheck(catalog: expression)` as
`RestageA2uiPreRenderCheck(catalogs: [expression])`. It does not regenerate
catalogs or migrate a handwritten GenUI host, transport, prompt, or cached
payload. Replace those host APIs manually with `MessageProcessor` and
`A2uiSurface`; give your producer the standard catalog JSON and its `instructions`.
Restage does not start or operate an agent service.

Code reading the removed public `.catalog` field must choose explicitly from
`.catalogs` (for example, `.catalogs.single` when exactly one is registered).
The Dart fix does not choose a catalog for a multi-catalog host.

`buildRestageCatalog()` supplies component schemas, instructions, and rich
catalog-level definitions. Manual `CatalogImplementation` composition must
merge **both** `buildRestageCatalogItems()` and
`buildRestageCatalogDefinitions()`, preserve the needed instructions, and assign
a new application-owned catalog ID to a changed schema/component set.

Component type names must satisfy upstream UAX31 identifiers and cannot be
`Surface`. Use `@RestageWidget(name: ...)` to choose a valid widget identity.
Native screens retain the exact `@Screen(id: ...)` / `@ScreenSource(id: ...)`
identity as their component type name: update invalid IDs and their consumers
explicitly. The generator never silently aliases them.

Component instance `id` values must also be UAX31 identifiers. Migrate producers
and cached payloads together, updating each renamed instance ID and all child
and template references to it. For example, rename `callout-body` to
`callout_body` in both the component declaration and every reference. The
`Surface` reservation applies to component type names, not instance IDs.
Instance IDs and their references require explicit migration; they are not
automatically aliased.

Controlled values keep explicit user paths unchanged. Literal/call local
write-back storage is `/restage_<URI-encoded component ID>/<generated property name>`,
with a `context_<URI-encoded data path>` segment before the property name inside
a template, so each row keeps its own value; this is internal fallback storage, not the component's identity. Data-model
bindings, local overrides, rebinding and disposal are qualified against the
published renderer in interaction tests.

See the [repository package README](https://github.com/restage-dev/restage/tree/main/packages/restage_a2ui)
for the full host example and executable interaction proofs.
