title: Coding agents
description: Install authoring and operations skills for Restage, from surface design to delivery and analytics.
---

The `restage` package ships two skills for your coding agent. Install both with one command, or pick the one you need. Each has a short entry point and detailed references the agent reads for the task at hand.

| Skill | Use it for |
| --- | --- |
| `restage-authoring` | Design surfaces for OTA updates, write screens and flows, connect host behavior, and verify generated mounts and delivered RFW. |
| `restage-operations` | Inspect deployed state, interpret analytics, diagnose delivery, manage routing and experiments, and publish or roll back. |

## Install the skills

Add `restage` to your app's dependencies. Then run this from the app's directory:

```sh
dart run skills@ get --package restage --all
```

Dart's [skills tool](https://pub.dev/packages/skills) reads the skills from the `restage` version your app resolves and asks which agent to install for. To pick the agent yourself:

```sh
dart run skills@ get --package restage --agent claude --all
```

Each agent has its own folder:

- `--agent claude` installs to `.claude/skills/`.
- `--agent cursor` installs to `.cursor/skills/`.
- `--agent codex` installs to `.agents/skills/`.

Leave out `--all` to choose individual skills. If your team shares the skills, commit them along with `.config/dart_skills/skills_config.json`, the file that records your selection.

After you upgrade `restage`, run the install command again. `dart run skills@ list` shows the installed skills. `dart run skills@ prune` removes skills from packages your app no longer depends on.

## Author with the recommended APIs

The authoring skill steers the agent to the generated `<Name>Surface(...)` mounts, automatic placements and your compiled widget as the fallback. `.atPlacement('name', ...)` is an optional way to name a placement yourself. Ordinary setup, Widgetbook and A2UI generation need no bundled surface assets.

It also teaches the agent how to keep a surface flexible over the air:

- Keep supported composition in the surface.
- Expose useful inputs and child slots.
- Read `restage build report` to see which parts render from native code.

It covers typed events, host data, branching and general flows, host actions, purchase integration and compiler failures.

After each build, the agent reads `restage build report`. It leaves the parts that render from the app alone unless you want one of them changeable over the air. It never rewrites code just to make a part render from the design.

The skill's source examples build in a real app, and its fallback and bundled-RFW paths are tested separately. A working fallback tells you nothing about delivered content.

## Operate with project context

The operations skill drives the [CLI and TUI](/tools/cli) or the [MCP server](/tools/mcp-server). It teaches the agent to:

- Choose a target and a time window.
- Read analytics.
- Diagnose delivery.
- Make reviewed routing changes.
- Draft, validate, review and activate an experiment.

Experiment operations don't need an experimental opt-in. Local surface authoring needs neither a hosted account nor an MCP connection.

The agent uses your existing authorization for the target and action you asked for. It asks before it does anything beyond that, or before it acts on impact it discovers along the way. Uploading a revision doesn't make it live. Publishing and routing change what the target serves, within the limits of compatibility and experiment assignment.

You still supply your app's credentials and purchase verification, and you approve browser sign-in when it's needed. The skills don't substitute example callbacks for real entitlement or platform behavior.

## Use the dashboard from a browser agent

The dashboard draws to a canvas. An agent reads it through the page's accessibility tree. When an automation tool drives the browser, the dashboard turns that tree on as it loads.

In a browser where `navigator.webdriver` is false, like your own browser driven through an extension, run this once after the page loads. Then take a new snapshot:

```js
document.querySelector('flt-semantics-placeholder').click()
```
