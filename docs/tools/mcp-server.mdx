title: MCP server
description: Let an MCP-capable agent or IDE manage your Restage surfaces, routing, products, and app settings.
---

`restage_mcp` is a [Model Context Protocol](https://modelcontextprotocol.io) server. It
lets an agent or IDE that speaks MCP, like Claude Code, Claude Desktop or Cursor, do what
you'd do with the `restage` CLI. The host starts it as a subprocess and talks to it over
standard input and output. It uses the same backend as the CLI.

<Callout type="info">
The source is public under BSD-3-Clause. It isn't on pub.dev yet.
</Callout>

## Install

Build it from a checkout of the repository:

```sh
git clone https://github.com/restage-dev/restage.git
cd restage
flutter pub get
mkdir -p "$HOME/.pub-cache/bin"
dart compile exe packages/restage_mcp/bin/restage_mcp.dart \
  -o "$HOME/.pub-cache/bin/restage_mcp"
```

Put `$HOME/.pub-cache/bin` on your `PATH`.

## Configure your MCP host

Every host runs the same command. In Claude Code:

```sh
claude mcp add restage -- restage_mcp
```

Claude Desktop and Cursor read an `mcpServers` object:

```json
{
  "mcpServers": {
    "restage": {
      "command": "restage_mcp"
    }
  }
}
```

A new sign-in goes to Restage Cloud. To sign in to another backend, set
`RESTAGE_BACKEND_URL` in `env`. Every tool then uses the backend you signed in to, and
the docs tools read that backend's docs.

## Sign in

Call `restage_login` to open your browser and show a short code. Approve the sign-in
there, then call `restage_login` again to finish.

`restage_whoami` shows who you're signed in as. `restage_logout` signs you out and deletes
the saved session.

The server and the CLI share one saved session. If you already ran `restage login`, the
server uses it and ignores `RESTAGE_BACKEND_URL`. No tool returns your session token.

## Tools

Your MCP host lists every tool with its full input schema. Tools marked admin need an
admin role. Each tool does what a `restage` CLI command does.

A tool that acts on an environment takes `environmentSlug`. If the environment exists on
both planes, it also takes `runtimePlane` (`sandbox` or `live`). A call without it is
refused. That way a call can't land on the wrong plane.

**Project setup.**

| Tool | What it does |
| --- | --- |
| `restage_status` | Show the account, the endpoint and the project your local `restage_config.yaml` points at. Names anything in it that doesn't exist. |
| `restage_init` | Set up a Flutter project for Restage. |
| `restage_doctor` | Check a Flutter project for common setup problems, including a `restage_config.yaml` that names things that don't exist. |

**Surfaces.** These work the same for onboarding, message, survey, paywall and general
surfaces. Pass `surfaceSlug`. Reads find the type from the slug, while changes also need `surfaceType`.

| Tool | What it does |
| --- | --- |
| `restage_list_surfaces` | List the surfaces in a project and app, of one type or all types. |
| `restage_surface_status` | Show a surface's live version, freeze state and delivery details. |
| `restage_surface_history` | List the revisions pushed to a surface. |
| `restage_surface_audit` | Show a surface's audit timeline. |
| `restage_read_surface_funnel` | Read views, steps, drop-off and completions for each published version over a time window. |
| `restage_push_surface` | Push generated surfaces from a local Flutter project, like `restage surface push`. |
| `restage_publish_surface` | Make a pushed revision live (admin). Defaults to the latest one pushed. `showInApp` says how to mount it in an app. |
| `restage_push_surface_draft` | Push a surface's saved dashboard draft as a new revision (admin). |
| `restage_pull_surface_draft` | Download a surface's saved dashboard draft as base64. |
| `restage_rollback_preflight` | Check a rollback against the current active version without changing anything. |
| `restage_rollback_surface` | Make an earlier published version live again, with a reason (admin). It can also freeze the surface. |
| `restage_kill_surface` | Stop hosted delivery (admin). Devices use content they saved earlier, or the fallback. |
| `restage_freeze_surface` / `restage_unfreeze_surface` | Block or allow new publishes of a surface (admin). |
| `restage_list_paywalls` | List paywalls under a project and app. |

**Pushing doesn't publish.** `restage_push_surface` uploads a version, and users see nothing new until `restage_publish_surface` makes it live. The routing tools change which
published version each audience gets.

After a kill, devices can still show content they saved earlier if it qualifies, or fall
back to what you configured. Content already on screen isn't necessarily removed right away.
Generated mounts include your compiled widgets as the fallback.

[Placements](/delivery/placements) covers the app setup and the review steps.

**Builds.** The dashboard can show a surface that uses your own widgets only after you
push a build of those widgets.

| Tool | What it does |
| --- | --- |
| `restage_list_builds` | List an app's builds, one per environment and one per user. |
| `restage_push_build` | Build your app's widgets for the web and push the build, like `restage build push`. It can take minutes. |
| `restage_push_catalog` | Upload the app's generated widget catalog. It lists your own widgets in the dashboard editor's palette. Devices and previews don't need it. |
| `restage_build_report` | Report what the last local build delivers and what renders from the app, like `restage build report --json`. Pass `accept` to record it as the baseline. |
| `restage_widget_promote` | Move a widget that renders from the app into a widget class of your own, like `restage widget promote`. |

`restage_build_report` has no `check` option. Read its `changes` field instead. It's absent when there's no baseline. `generatedErrors` lists any generated part that doesn't compile. Keep the parts that render from the app unless the developer wants to change or test what they cover. Never rewrite code only to remove one.

The report suggests `restage_widget_promote` when the same code renders from the app in several screens, or when a widget takes three or more values from the design. Use it only when the developer wants the code named and reusable. [What renders from your app](/authoring/islands) explains the parts.

| `restage_list_apps` | The apps in a project. |
| `restage_list_environments` | The environments in a project. |

**Audit.** `restage_audit_log`, `restage_audit_export` and `restage_audit_verdict` read
the organization's audit log, its compliance rows, and whether its audit chain verifies.
Each row's `chain` is `pending`, `chained` (no verification run has reached it yet) or
`verified`.

**Products and stores.**

| Tool | What it does |
| --- | --- |
| `restage_list_products` | An app's store products. |
| `restage_import_products` | Fetch a store's catalog again and update the products (admin). |
| `restage_list_product_slots` | Product slots and which products they map to. |
| `restage_upsert_product_slot` | Create or change a slot and its whole product mapping (admin). |
| `restage_list_store_connections` | Store connections, without secrets. |

`restage_upsert_product_slot` replaces the whole mapping, and a store you pass as `null` is unmapped. List the slots first and pass back any mapping you want to keep.

**Analytics and experiment results.**

| Tool | What it does |
| --- | --- |
| `restage_read_analytics_overview` | Read overall analytics for the selected target. |
| `restage_read_explore` | Read analytics grouped by a dimension such as platform. |
| `restage_read_surface_analytics` / `restage_read_surface_taps` | Read a surface's metrics or taps. |
| `restage_read_data_health` | Check measurement health. |
| `restage_read_experiments` / `restage_read_experiment` | List experiments or read one experiment's results. |

These reads are always registered, and each tool's schema lists its target and time window. Most analytics default to the last 30 days, while experiment results default to the whole current run. Dates filter only the traffic breakdowns, and the statistical result always covers the whole run as designed. Don't read a withheld or unavailable value as zero.

**Experiment authoring.** `restage_experiment_apply` is registered by default. Use it to
create and edit a draft, validate it, review its current revision, then activate that
reviewed revision. Read the results before you pause, resume or conclude, and pass `confirmLive: true` for live lifecycle changes. [Experiments](/delivery/experiments) has the workflow
and the operation arguments.

`restage_apply_canonical_mutation` and `restage_activate_experiment` are low-level tools
that still need `RESTAGE_EXPERIMENTAL=1`. Ordinary experiment authoring doesn't use them.

For routing, pass the review that `restage_review_routing` returned, unchanged, as
`reviewBase64` to `restage_publish_routing`. The preview tool takes a simulation request
and the review tool takes a review request. The
[Audience routing guide](/delivery/audience-routing) explains the difference.

## Review experiment impact

Publish, rollback, kill, freeze and unfreeze check how a change affects measurement
before they apply it. To see that check first, call the tool with `reviewOnly: true`. You
get a `measurementReview` and a `reviewDigest`, and the surface doesn't change. When you
publish, pass an explicit revision so you publish the one you reviewed.

Read which experiments, metrics and versions are affected, and what each warning means.
If the review shows an impact the user hasn't approved, explain it and stop. Once the
user approves, repeat the same call with `reviewOnly` left out or false and
`reviewedDigest` set to the digest you got back. A review with no warnings needs no
acknowledgment.

Pick a lowercase UUIDv4 for `operationId` and reuse it, with the same inputs, when you
retry. If you can't tell whether a call went through, check status and history first.
A refusal blocks the change. If the review is out of date or has changed, inspect it
again. Never copy a digest out of an error just to make a call succeed. Warning errors
include `acknowledgementRequired: true` and the full review.

On live targets, these calls also need a reason and `confirmLive: true` after the user
approves, even with `reviewOnly: true`. `confirmLive` confirms only the live change.
Measurement warnings need their own acknowledgment. Sandbox targets skip the live
confirmation and still check measurement impact.

`restage_rollback_preflight` checks compatibility against the current active version. It's
separate from the rollback tool's measurement review, and it doesn't prove the version
works on every installed app. Routing has its own
[policy review and acknowledgment](/delivery/audience-routing#simulate-and-review-a-policy).

## Keeping secrets out of the chat

Pass ids, slugs and ordinary settings as tool arguments. Don't pass API keys or tokens.
If an argument fails validation, your MCP host may repeat it in the error.

The server strips your session token and the sign-in code from every tool result.
Internal errors come back as a fixed message with no stack trace. A damaged credentials
file never leaks its contents into a result. None of this protects you from a compromised
backend. The backend already holds your session.
