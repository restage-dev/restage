title: MCP server
description: Let an MCP-capable agent or IDE manage your Restage surfaces, routing, products, and app settings.
---

`restage_mcp` is a [Model Context Protocol](https://modelcontextprotocol.io) server for
Restage. An agent or IDE that speaks MCP, such as Claude Code, Claude Desktop, or
Cursor, launches it as a subprocess and talks to it over standard input and output. It
reaches the same backend as the `restage` CLI.

The source is public under BSD-3-Clause. It isn't on pub.dev yet.

## Install

Build it from a checkout of the repository:

```sh
git clone https://github.com/restage-dev/restage.git
cd restage
flutter pub get
mkdir -p "$HOME/.pub-cache/bin"
dart compile exe packages/restage_mcp/bin/restage_mcp.dart \
  -o "$HOME/.pub-cache/bin/restage_mcp"
```

Make sure `$HOME/.pub-cache/bin` is on your `PATH`.

## Configure your MCP host

Every host runs the same command. For Claude Code:

```sh
claude mcp add restage -- restage_mcp
```

For a host that reads an `mcpServers` object, such as Claude Desktop or Cursor:

```json
{
  "mcpServers": {
    "restage": {
      "command": "restage_mcp"
    }
  }
}
```

A new sign-in uses Restage Cloud (`https://api.restage.dev/`). Set
`RESTAGE_BACKEND_URL` in `env` to sign in to another backend. After sign-in, each tool
uses the backend your session was created against.

## Sign in

Call `restage_login`. It opens your browser and shows a short code. Approve the sign-in
there, then call `restage_login` again to finish. `restage_whoami` reports who you are
signed in as, and `restage_logout` signs out and removes the saved session.

The MCP server and the CLI share one saved session. If you already ran `restage login`,
the server uses that session and ignores `RESTAGE_BACKEND_URL`. No tool ever returns
your session token.

## Tools

Your MCP host lists every tool with its full input schema. Tools marked admin need an
admin role.

Every tool does what a `restage` CLI command does. A tool that acts on an environment
takes `environmentSlug`, plus `runtimePlane` (`sandbox` or `live`) when that environment
exists on both planes. Without it, such a call is refused, so it never reaches the
wrong plane.

**Project setup.**

| Tool | What it does |
| --- | --- |
| `restage_status` | Report the account, endpoint, and the project a local `restage_config.yaml` points at, and name anything in it that does not exist. |
| `restage_init` | Set up a Flutter project for Restage. |
| `restage_doctor` | Check a Flutter project for common setup issues, including a `restage_config.yaml` that names things that do not exist. |

**Surfaces.** These work the same for onboarding, message, survey, paywall, and general
surfaces. Pass `surfaceSlug`. Reads look up the type from the slug; changes also need
`surfaceType`.

| Tool | What it does |
| --- | --- |
| `restage_list_surfaces` | List surfaces under a project and app, of one type or of every type. |
| `restage_surface_status` | Show the live version, freeze state, and delivery details for one surface. |
| `restage_surface_history` | List the revisions pushed to one surface. |
| `restage_surface_audit` | Show the audit timeline for one surface. |
| `restage_read_surface_funnel` | Read views, steps, drop-off, and completions per published version over a time window. |
| `restage_push_surface` | Push generated surfaces from a local Flutter project, like `restage surface push`. |
| `restage_publish_surface` | Publish a pushed revision so it serves (admin). Defaults to the latest one pushed. `showInApp` says how to mount it in an app. |
| `restage_push_surface_draft` | Push a surface's saved dashboard draft as a new revision (admin). |
| `restage_pull_surface_draft` | Download a surface's saved dashboard draft as base64. |
| `restage_rollback_preflight` | Compare a rollback's compatibility with the current active version without changing anything. |
| `restage_rollback_surface` | Make an earlier published version live again, with a reason (admin). It can also freeze the surface. |
| `restage_kill_surface` | Stop hosted delivery; devices use content they saved earlier or their fallback (admin). |
| `restage_freeze_surface` / `restage_unfreeze_surface` | Stop or allow new publishes of a surface (admin). |
| `restage_list_paywalls` | List paywalls under a project and app. |

**Pushing does not publish.** `restage_push_surface` uploads a version and changes
nothing users see. `restage_publish_surface` makes it live. The routing tools change
which published version each audience receives.

After a kill, devices may use content they saved earlier that still qualifies, or
their configured fallback. Content already displayed is not necessarily removed immediately.
Generated mounts include the original Flutter widgets as fallback.

| --- | --- |

| `restage_push_catalog` | Upload the app's generated widget catalog, which lists your own widgets in the dashboard editor's palette. Devices and previews do not need it. |

| Tool | What it does |
| --- | --- |
| `restage_list_organizations` | The organizations you belong to. |
| `restage_list_projects` | Projects under an organization. |
| `restage_list_apps` | Apps under a project. |
| `restage_list_environments` | Environments under a project. |
| `restage_list_environment_targets` | Environment targets under an app. |

only once. Create keys in the dashboard.

**Audit.** `restage_audit_log`, `restage_audit_export`, and `restage_audit_verdict` read
the organization's audit log, its compliance rows, and whether its audit chain verifies.
Each row's `chain` is `pending`, `chained` (not yet reached by a verification run), or
`verified`.

**Products and stores.**

| Tool | What it does |
| --- | --- |
| `restage_list_products` | Store products for an app. |
| `restage_import_products` | Fetch a store's catalog again and update the products (admin). |
| `restage_list_product_slots` | Product slots and their product mappings. |
| `restage_upsert_product_slot` | Create or update a slot and its whole product mapping (admin). |
| `restage_list_store_connections` | Store connections, without secrets. |

`restage_upsert_product_slot` replaces the whole mapping. A store you pass as `null` is
unmapped, so list the slots first and pass back any mapping you want to keep.

**Analytics and experiment results**

| Tool | What it does |
| --- | --- |
| `restage_read_analytics_overview` | Read aggregate analytics for the selected target. |
| `restage_read_explore` | Read analytics grouped by a supported dimension. |
| `restage_read_surface_analytics` / `restage_read_surface_taps` | Read a surface's metrics or taps. |
| `restage_read_data_health` | Inspect measurement health. |
| `restage_read_experiments` / `restage_read_experiment` | List experiments or read one experiment's results. |

These reads are always registered. Use each tool's schema for its target and
time window. Most analytics default to the last 30 days; experiment results
default to the whole current run. Dates filter only the traffic breakdowns; the
statistical result always covers the whole run as designed. Withheld or
unavailable values must not be read as zero.

**Experiment authoring.** `restage_experiment_apply` is registered by default. Create and edit a
draft, validate it, review its current revision, then activate that reviewed
revision. Read results before pausing, resuming or concluding it. Live lifecycle
changes require `confirmLive: true`. See [Experiments](/delivery/experiments) for
the workflow and operation arguments.

Two low-level tools, `restage_apply_canonical_mutation` and
`restage_activate_experiment`, still need `RESTAGE_EXPERIMENTAL=1`; ordinary
experiment authoring doesn't use them.

For routing, use the original review returned by `restage_review_routing` as
`reviewBase64` in `restage_publish_routing`. The preview tool takes a simulation
request; the review tool takes a review request. The
[Audience routing guide](/delivery/audience-routing) explains the distinction.

## Review experiment impact

Surface publish, rollback, kill, freeze and unfreeze review measurement impact
before applying a change. Call the intended tool with `reviewOnly: true` to
inspect its `measurementReview` and `reviewDigest` without changing the surface.
Pass an explicit revision when publishing, so you publish the exact revision you
reviewed.

Read the affected experiments, metrics, versions and what each warning means. If
the review shows impact the user hasn't approved, explain it and stop before
applying. Once the user approves, repeat the exact operation with `reviewOnly`
omitted or false and `reviewedDigest` set to the returned digest. A review with no
warnings needs no acknowledgment.

Choose a lowercase UUIDv4 as `operationId` and reuse it with the same inputs when
you retry. When you can't tell whether a call went through, check status and
history before retrying. Refusals block the change; an out-of-date or changed
review must be inspected again.
An agent must not copy a digest from an error simply to make a call succeed.
Warning errors include `acknowledgementRequired: true` and the full review.

On live targets, these operations also need a reason and `confirmLive: true`
after user approval, including when `reviewOnly` is true. This confirms only the
live change; measurement warnings need their own acknowledgment. Sandbox targets
skip the live confirmation and still check measurement impact.

`restage_rollback_preflight` checks compatibility against the current active
version. It is separate from the rollback tool's measurement review and does
not prove compatibility with every installed app. Routing uses its own
[policy review and acknowledgment](/delivery/audience-routing#simulate-and-review-a-policy).

## Keeping secrets out of the chat

Pass ids, slugs, and ordinary settings as tool arguments. Don't pass API keys or tokens:
if an argument fails validation, your MCP host may repeat it in the error.

The server removes your session token and the sign-in code from every tool result.
Internal errors come back as a fixed message, with no stack trace. A damaged credentials
file never leaks its contents into a result. None of this protects you from a
compromised backend, which already holds your session.
